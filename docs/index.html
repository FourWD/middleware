Overview

github.com/FourWD/middleware is the shared Go library every Pakkad backend service imports. It bundles application bootstrap, HTTP framework wiring, persistence clients (SQL, Mongo, Redis), Firebase, Pub/Sub, Cloud Storage, JWT auth, observability and rate-limit middleware behind a single infra.NewApp(registrar) entry point.

v1 Owned by: @puarns · Last reviewed: 2026-05-24

1.1 Background & Objective

Pakkad operates a fleet of Go services (vehicle ops, finance, customer portal, payment relay, GPS ingest, etc.). Before this repository existed each service rolled its own bootstrap, env loading, logger, JWT, Fiber stack and database pool. The drift made cross-service changes (new header, new metric, new auth claim) painful and inconsistent.

The objective of middleware is to own the infrastructure surface so that a project repository contains only business code (handlers, ORM models, use-cases) and a thin RouteRegistrar that wires routes onto the Fiber app this library hands out.

Note — this is a library, not a deployable service. The only runnable artefact here is the test suite; everything else is consumed via Go modules from downstream service repositories.

1.3 Target Users

The audience for this library is internal Pakkad backend engineers maintaining or building a Go service on top of it. There are no end-user surfaces.

  • Service authors — implement a RouteRegistrar, call infra.NewApp(registrar).Run() from main, and focus on domain code.
  • Platform / infra engineers — change the default middleware stack, add a new infra client, or evolve the auth surface here so every downstream service inherits the change.
  • Operators on call — read this doc set to know which env vars exist, which endpoints come for free, and which failures fall back to which behaviour.

1.4 Business Rules

These are non-domain rules that apply to every service that imports this library. They are enforced in code (validators, defaults, middleware) — not documentation conventions.

  1. BR-1 — APP_ID is the single service identity. Logs, metrics, OTel resource, JWT issuer, rate-limit key prefix all derive from APP_ID. On Google App Engine GAE_SERVICE overrides it automatically so the deployed name always wins.
  2. BR-2 — APP_ENV is constrained. Only local, dev, prod, test are accepted; any other value fails startup. Debug routes are disabled when APP_ENV=prod.
  3. BR-3 — JWT_SECRET is mandatory. Boot fails fast if it is empty, even for services that never issue tokens, because middleware presence is uniform.
  4. BR-4 — Primary database is opt-out. Leaving DB_NAME empty disables the primary pool and the migration runner; gateway / webhook-relay services can run stateless.
  5. BR-5 — JWT blacklist requires a store. Setting JWT_BLACKLIST_ENABLED=true without MONGO_MIDDLEWARE_ENABLED or REDIS_ENABLED is a startup error. MongoMiddleware wins over Redis when both are present.
  6. BR-6 — Refresh tokens are one-shot. TokenManager.Refresh revokes the presented refresh token before issuing the new pair; replays return ErrRevokedToken.
  7. BR-7 — Rate limit has three tiers. Strict (per-minute, auth endpoints), default (per-second, regular API), skip (no middleware) — selected at route-group registration, not by env.
  8. BR-8 — Public paths are exact-match only. HTTP_PUBLIC_PATHS and AuthMiddlewareV2Config.ExemptPaths are matched literally; no prefix, no regex. Service-built-ins (/_ah/warmup, /wake-up, /livez, /readyz, /healthz, /metrics) are auto-exempt.
  9. BR-9 — Responses use the envelope. Successful responses are { success:true, data }; errors are { success:false, error:{ code, message } }. Internal error details are never leaked to clients.
  10. BR-10 — Shutdown is bounded. On SIGINT/SIGTERM workers get cancelled, Fiber gets up to 10 s, then cleanup hooks run in reverse order with a 5 s budget. Hooks that hang past their budget are abandoned.
  11. BR-11 — Cron paths need both the path and the header. CRON_PATHS (and AuthMiddlewareV2Config.CronPaths) skip auth only when the request also carries X-Appengine-Cron: true. A listed path alone still requires a token; the header alone never widens access beyond the listed paths. App Engine strips inbound X-Appengine-* headers, so this is safe only behind App Engine — never on a service exposed directly to the internet. Cron requests carry no session: GetSession returns nil and AuthSessionFrom returns ok=false, so a cron route must not be wrapped in AdminOnly.

1.5 Glossary

A service is a single deployable Go binary (one main) that imports this library and ships its own routes, migrations and configuration.

A registrar is the RouteRegistrar function a service implements; infra.NewApp calls it once with all initialised dependencies so the service can mount routes and project-specific middleware.

The envelope is the uniform JSON wrapper {success, data, error} emitted by WriteSuccess / WriteErrorEnvelope. It is the on-the-wire contract every Pakkad client (web, mobile, internal) expects.

The token manager is infra.TokenManager — it owns access/refresh JWT generation, parsing, refresh rotation and revocation, backed by a RefreshTokenStore.

The blacklist is infra.BlacklistStore — a Mongo- or Redis-backed set of revoked access-token strings consulted by Auth V2 on every authenticated request.

The heartbeat is the in-process scheduler that pings configured liveness probes on an interval; its current circuit state is exposed via /debug/background-jobs/heartbeat/circuit-state.

A worker is a long-running background goroutine registered via deps.Runtime.RegisterWorker; App.Run manages its lifecycle alongside the HTTP server.
