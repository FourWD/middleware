🔴 ปัญหาเดิม

cron path ถูกใส่ไว้ใน HTTP_PUBLIC_PATHS เพื่อให้ App Engine Cron เรียกได้ ผลคือ ใครก็ยิงได้ เพราะ public path ไม่เช็คอะไรเลย

แต่ถ้าเอาออกจาก HTTP_PUBLIC_PATHS เฉยๆ cron ที่ไม่มี JWT จะโดน 401 No token provided ก่อนถึง handler

🎯 สิ่งที่ทำ

เพิ่ม env CRON_PATHS (CSV เหมือน HTTP_PUBLIC_PATHS) — path ในลิสต์นี้ข้าม JWT auth ได้ เฉพาะเมื่อ request มาจาก App Engine Cron คนอื่นยังโดน 401 ตามเดิม

1พฤติกรรม

ต้องครบ ทั้งสองเงื่อนไข จึงจะข้าม auth — path อยู่ในลิสต์ และ มี header

Requestผลลัพธ์
path อยู่ใน CRON_PATHS + X-Appengine-Cron: true ผ่าน — ไม่ต้องมี token
path อยู่ใน CRON_PATHS แต่ไม่มี header 401 — ยังต้องมี token
มี header แต่ path ไม่อยู่ในลิสต์ 401 — header ขยายสิทธิ์เกินลิสต์ไม่ได้
ค่า header ไม่ใช่ true เป๊ะ (TRUE, 1, …) 401
CRON_PATHS ว่าง / ไม่ได้ตั้ง ปิดสนิท — ไม่มี bypass

2ทำไมถึงเชื่อ header ได้

App Engine strip header X-Appengine-* ทุกตัวออกจาก request ที่มาจากภายนอก ดังนั้นถ้า handler เห็น X-Appengine-Cron: true แปลว่ามันถูกใส่โดย Cron service เท่านั้น — นี่คือ security boundary ที่ Google รับประกัน ไม่ใช่แค่ hint

หมายเหตุ: ไม่ได้บังคับ X-Appengine-QueueName / X-Appengine-TaskName เพิ่ม เพราะสอง header นั้นเป็นของ Task Queue รันไทม์ 2nd-gen อาจไม่ส่งมาเลย และมันมาจาก source เดียวกันกับ X-Appengine-Cron — บังคับเพิ่มไม่ได้กันการปลอมแปลง แต่เสี่ยงทำให้ cron พังแทน

infra/cron_paths.go

// appEngineCronHeader is set by the App Engine Cron service. App Engine strips
// every X-Appengine-* header from external requests, so its presence is an
// authentication signal, not a hint.
const appEngineCronHeader = "X-Appengine-Cron"

var cronPaths = sync.OnceValue(func() *publicPathMatcher {
    return newPathMatcher(CronPathsFromEnv())
})

func CronPathsFromEnv() []string {
    return SplitCSV(GetEnv("CRON_PATHS", ""))
}

func isAppEngineCronRequest(c fiber.Ctx, paths *publicPathMatcher) bool {
    if c.Get(appEngineCronHeader) != "true" {
        return false
    }
    return paths.matches(c.Path())
}

infra/auth_middleware.go (v1)

func AuthenticationMiddleware(c fiber.Ctx) error {
    if publicPaths().matches(c.Path()) {
        return c.Next()
    }
    if isAppEngineCronRequest(c, cronPaths()) {
        return c.Next()
    }
    return checkAuth(c)
}

4ขั้นตอนฝั่ง Duckbook

  1. Bump version FourWD/middleware

    รัน go get github.com/FourWD/middleware@<new-tag> และ go mod tidy

  2. ยืนยัน header จริงก่อน

    ยิง cron manual จาก Cloud Console (เมนู ⋮ → Run now) แล้วดู request log ว่ามี X-Appengine-Cron มาจริง — ทำก่อนขั้นถัดไปเพื่อไม่ให้ cron ค้างเป็น 401

  3. เพิ่ม CRON_PATHS ใน .env.dev / .env.prod 
    CRON_PATHS=/api/v1/clean-service/clean-model/cron,/api/v1/scraping-service/digest/cron,/api/v1/sync-service/sync-md2db/cron

    หรือใช้ regex ตัวเดียว: CRON_PATHS=^/api/v1/.*/cron$

  4. ลบ 3 path นั้นออกจาก HTTP_PUBLIC_PATHS

    ถ้ายังค้างอยู่ public path จะ match ก่อน แล้ว cron check ไม่ทำงาน — path ก็ยังเปิดให้คนนอกเหมือนเดิม ขั้นนี้คือขั้นที่ทำให้ปลอดภัยขึ้นจริง

  5. เช็ค handler ว่าไม่พึ่ง session

    cron request ไม่มี claims — infra.GetSession คืน nil และยิง log SESSION_INVALID_SIGNATURE ทุกครั้ง ถ้า handler ตัวไหนเรียก GetSession / GetSessionUserID ต้องแก้

  6. ลบ header check ซ้ำใน handler

    handlers/admin/clean-model/clean-model-handler.go เช็ค X-Appengine-Cron เองอยู่ ตอนนี้เป็น logic เดียวกันซ้ำสองที่ — ลบออกได้ ให้เหลือจุดเดียวที่ middleware

  7. ทดสอบ cron จริงทั้ง 3 job

    ยืนยันว่าวิ่งถึง handler และยิง path เดียวกันจากภายนอกโดยไม่มี token ต้องได้ 401

!ข้อควรระวัง

  1. ใช้ได้เฉพาะหลัง App Engine — ถ้าย้ายไป Cloud Run / ตั้ง LB เอง / เปิดรับ request จาก internet ตรงๆ ต้องลบ CRON_PATHS ทันที เพราะไม่มีใคร strip header ให้แล้ว
  2. cron request ไม่มี session — AuthSessionFrom คืน ok=false และ GetSession คืน nil อย่าเอา cron route ไปห่อด้วย AdminOnly
  3. ลำดับสำคัญ — HTTP_PUBLIC_PATHS ถูกเช็คก่อน ถ้า path ซ้ำกันสองที่ cron check จะไม่มีผล
  4. ค่าเริ่มต้นปิด — CRON_PATHS ว่าง = ไม่มี bypass ทุก project เดิมไม่กระทบ
  5. ค่า header ต้องเป็น true เป๊ะ (case-sensitive) — TRUE / 1 ไม่ผ่าน
