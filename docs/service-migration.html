Service Migration Runbook

Step-by-step guide for service repos upgrading to the new logging standard introduced by middleware. Covers two soft-breaking areas: deprecated common.Log/LogError/LogWarning bridges and deprecated Level methods on *Logger.

v1 Owned by: @puarns · Last reviewed: 2026-05-24

1. Compatibility Posture

The middleware library makes deprecations soft — old call sites compile and run, but emit // Deprecated: warnings in IDE / staticcheck / golangci-lint. Service repos can migrate at their own pace; nothing breaks on version bump.

Note — infra.AppLog remains a plain package var. Existing infra.AppLog.X(...) call sites continue to work; the deprecation only flags the legacy bridge in common/log.go and the Level methods on *Logger.

2. Phase 1 — Replace common.Log* bridges

Goal: remove all common.Log / common.LogError / common.LogWarning calls.

Mapping

Old callNew call
common.Log("LABEL", data, requestID) infra.AppLog.Event("LABEL", data, requestID, infra.WithComponent("…"), infra.WithOperation("…"), infra.WithLogKind(infra.LogKindBusiness))
common.LogWarning("LABEL", data, requestID) infra.AppLog.EventWarn(...)
common.LogError("LABEL", data, requestID, err) infra.AppLog.EventError(err, "LABEL", data, requestID, opts...)

Pattern: prefer EventCtx when a request context is in scope

// before
common.LogError("USER_CREATE_FAILED", map[string]interface{}{
    "userID": id,
    "error":  err.Error(),
}, requestID, err)

// after
infra.AppLog.ErrorCtx(c.Context(), err, "USER_CREATE_FAILURE", nil,
    infra.WithComponent(infra.ComponentHandler),
    infra.WithOperation("create_user"),
    infra.WithLogKind(infra.LogKindError),
    infra.WithField("user_id", id))

Notes:

  • Label format: UPPER_SNAKE, shape <DOMAIN>_<OPERATION>_<OUTCOME>. Old camelCase / lower-snake labels should be renamed for grep-ability.
  • Error duplication: do NOT pack the error string into both the positional err arg and a data["error"] field — the logger emits a top-level error attribute automatically.
  • PII: never log raw tokens, mobile numbers, email locals, passwords. Use kit.MaskMobile / kit.MaskEmail for safe forms.

3. Phase 2 — Migrate deprecated Level methods

Goal: stop calling logger.Info/Warn/Error/CriticalWarning/CriticalError outside lifecycle code. They remain on the type for backwards compatibility and request-log severity routing, but the recommended replacements are:

OldNew
logger.Info(M("worker started"), …) logger.LifecycleEvent("WORKER_STARTED", nil, opts...)
logger.Warn(M("…"), …) (lifecycle) logger.LifecycleWarn(label, data, opts...)
logger.Error(err, M("…"), …) (lifecycle) logger.LifecycleError(err, label, data, opts...)
logger.Info(M("…"), …) (business event) logger.EventCtx(ctx, label, data, opts...)
logger.Error(err, M("…"), …) (request handler) logger.ErrorCtx(ctx, err, label, data, opts...)

The Lifecycle helpers auto-stamp WithLogKind(LogKindLifecycle) as a default; if the caller passes their own WithLogKind it wins.

4. Phase 3 — Adopt helpers for common patterns

Optional but recommended: collapse boilerplate using the helpers in infra/log_helpers.go.

PatternHelper
DB op failed infra.LogDBError(ctx, err, "create", "users", id)
Outbound HTTP failed infra.LogHTTPClientError(ctx, err, "POST", url, status)
Domain event (audit) infra.LogBusinessEvent(ctx, "USER_CREATED", "handler", "create_user", data)
Boot/shutdown event infra.LogLifecycle("WORKER_STARTED", "app", "worker_start", data)

5. Phase 4 — Adopt custom error codes (optional)

Domain errors that satisfy infra.ErrorWithCode (Code() string method) automatically contribute an error_code attribute. No dependency on infra.AppError required. 

// internal/domain/errors.go
type UserNotFound struct{ ID string }

func (e UserNotFound) Error() string { return "user not found: " + e.ID }
func (e UserNotFound) Code() string  { return "USER_NOT_FOUND" }

// usage — code automatically tagged onto the log entry
return infra.AppLog.ErrorCtx(ctx, UserNotFound{ID: id}, "LOOKUP", nil, opts...)

6. Verification

  • Run go vet ./... in the service repo — should be clean.
  • Run go build ./... — should be clean.
  • Run staticcheck ./... (or golangci-lint run) — deprecation warnings on remaining common.Log* / Level-method call sites highlight what still needs to migrate.
  • Spot-check Cloud Logging for the service in a dev environment: every log line should carry component, operation, log_kind, and a UPPER_SNAKE label.

7. Rollback

Every step is reversible:

  • Phase 1: common.Log/LogError/LogWarning still exist as deprecated shims — reverting one file at a time is safe.
  • Phase 2: Level methods still exist on *Logger; reverting to logger.Info(M("…"), …) compiles.

8. Timeline expectations

Per service:

  • Phase 1 (common.Log): 30–60 minutes depending on call-site count.
  • Phase 2 (Level → Lifecycle/Event): 1–2 hours; mechanical but requires judgement on label naming.
  • Phase 3 (helpers): optional, do opportunistically.
  • Phase 4 (custom error codes): optional, do when introducing new domain error types.

All required phases for a typical service: ~2–3 hours of focused work.
