Database

The library owns three persistence surfaces: GORM-backed SQL pools (MySQL or Postgres, with optional Cloud SQL Unix socket), MongoDB (two independent clients — business and middleware) and Redis. The orm package ships shared GORM models reused across services; this library itself stores only two Mongo collections — blacklist_tokens and refresh_tokens — used by auth.

3.2 Schema

3.2.1 SQL connection model (MySQL / Postgres)

Driver is selected by DB_DRIVER (or DB2_DRIVER). DSN is assembled by BuildMySQLDSN or BuildPostgresDSN; when DB_INSTANCE is set the MySQL DSN switches to a Cloud SQL Unix socket at /cloudsql/<instance> and the host/port fields are ignored.

DriverDSN template
mysql (TCP)user:pass@tcp(host:port)/name?charset=utf8mb4&parseTime=True&loc=Local
mysql (Cloud SQL)user:pass@unix(/cloudsql/<DB_INSTANCE>)/name?…
postgreshost=… user=… password=… dbname=… port=… sslmode=disable TimeZone=UTC

3.2.2 Pool tuning

Each pool sets SetMaxIdleConns, SetMaxOpenConns and SetConnMaxLifetime from env. Defaults below; OpenTelemetry tracing is auto-registered via gorm.io/plugin/opentelemetry.

3.2.5 Shared orm models

The orm package ships 117 GORM model files reused across services (vehicle, booking, finance, log, survey, etc.). Every domain row embeds the common model.GormModel mixin below; soft-delete is on by default via gorm.DeletedAt. 

package model

type GormModel struct {
    CreatedAt time.Time      `gorm:"<-:create"`
    UpdatedAt time.Time
    DeletedAt gorm.DeletedAt `gorm:"index"`
    CreatedBy string         `gorm:"type:varchar(36)"`
    UpdatedBy string         `gorm:"type:varchar(36)"`
    DeletedBy string         `gorm:"type:varchar(36)"`
}

Conventions enforced by the existing models in orm/:

  • Primary key is always id varchar(36) (UUID) with uniqueIndex:idx_id; integer auto-increment RunningNo is added where humans need a stable monotonic reference.
  • FK columns are bare varchar(36) — relations are described in code, not at the schema level.
  • Lookup tables use a short typed code: varchar(2) for two-character status/type IDs.
  • Soft delete is always on; physical deletes happen through migration scripts only, not the API.

3.3 Data Migration

infra.RunMigrations(cfg) runs golang-migrate/migrate/v4 against the primary pool at boot. The runner is a no-op when MIGRATIONS_ENABLED=false or the migrations directory has no files; this means a service can ship without migrations and still boot.

SettingEnvDefault
EnabledMIGRATIONS_ENABLEDfalse
Source directoryMIGRATIONS_PATHmigrations (relative to working dir)

File naming

Each service owns its migration files. They follow the standard golang-migrate convention: 

migrations/
  0001_init.up.sql
  0001_init.down.sql
  0002_add_user_status.up.sql
  0002_add_user_status.down.sql

Rollback

The runner only calls Up() — there is no auto-rollback. Manual rollback is performed via the migrate CLI against the same database with the same source URL: 

migrate -path ./migrations \
        -database "mysql://user:pass@tcp(host:3306)/name" \
        down 1
Warn — migrations run synchronously before OpenDB opens the application pool. A failing migration aborts boot. Schema-altering migrations that take minutes on a large table should be applied out-of-band first, then committed as a no-op file to bring the version table in sync.

3.4 Seed Data

The library does not ship seed data. Per-service seeds (lookup tables, default roles, admin user) live in the consuming service's migrations/ directory as additional .up.sql files so the migration runner brings them in alongside the schema.

3.5 Throughput Patterns

The library does not impose query patterns on service code. The two throughput surfaces it does provide:

  • DB pool metrics — registerDBMetrics exposes a Prometheus collector that scrapes sql.DBStats lazily on each /metrics hit. Watch db_open_connections, db_wait_count, db_wait_duration_seconds_total for pool saturation.
  • Rate-limit Lua script — the strict and default tiers run a single round-trip INCR + conditional EXPIRE script (rateLimitScript in infra/rate_limit.go) so a counter never lingers without TTL even if the second command races. The fallback in-memory store sweeps expired keys every 30 s.
