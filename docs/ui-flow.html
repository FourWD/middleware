UI & Flow

The library has no end-user UI. "Flows" here describe the runtime sequences operators and service authors deal with: boot, request, auth, and shutdown. Each flow lists the actors, the order of effects, the success path and the documented failure branches.

2.1 User Flows

UF-1 — Service boot via infra.NewApp

A service's main calls infra.NewApp(registrar).Run(). NewApp performs all infra initialisation in a fixed order; any step that returns an error runs accumulated cleanup hooks and aborts boot. 

main()
  └─ infra.NewApp(registrar)
       1. LoadEnvFiles        .env → .env.{APP_ENV}   (existing env wins)
       2. LoadCommonConfig    CommonConfig from env (APP_ID, DB, Redis, …)
       3. validateCommonConfig fail-fast on bad values
       4. NewLoggerWith        structured logger (slog, JSON in non-local)
       5. initGlobals + tz     bind globals, set process timezone
       6. SetupSentry          register Sentry transport (optional)
       7. SetupOTel            OTLP tracer + meter (optional)
       8. initInfrastructure   DB, Redis, Mongo, Firebase, PubSub, Storage, Mail
       9. bindDatabaseGlobal   wire global infra.Database for legacy callers
      10. ensureAuthStoreIndexes  best-effort Mongo TTL/index create (async)
      11. buildRateLimiter    Redis-backed if REDIS_ENABLED, else in-memory
      12. registerDBMetrics    Prometheus pool collector
      13. registerGAEVersionCheck  background poller (GAE only)
      14. NewHeartbeatScheduler   gocron jobs
      15. NewFiberApp + RegisterStack
      16. registerDefaultRoutes  /_ah/warmup, /wake-up
      17. registrar(web, deps)   PROJECT CODE — mount routes
      18. start heartbeat       if scheduler is non-nil
  └─ App.Run()
       19. spawn workers
       20. fiber.Listen
       21. wait SIGINT / SIGTERM
       22. cancel engine → wait workers (≤ 10 s)
       23. fiber.ShutdownWithContext (≤ 10 s)
       24. run shutdown hooks LIFO (≤ 5 s)
Note — the registrar is the only hook for project-specific code. Auth middleware, migrations and project routes all live there. NewApp deliberately does not call AuthenticationMiddleware automatically because not every service uses the same gate (V1 vs V2, custom Firebase-token middleware, etc.).

UF-2 — Authenticated HTTP request (V2 stack)

The default stack RegisterStack mounts middleware in a fixed order. Auth V2 sits at the registrar layer, after the base stack, before any business middleware. 

HTTP request
  │
  ├─ RequestID           inject X-Request-ID, stamp ctx
  ├─ CORS                Allow-Origin from HTTP_ALLOW_ORIGINS
  ├─ Sentry              recover panic → Sentry event
  ├─ Recover             secondary panic guard, 500 envelope
  ├─ OTel                start server span, attach trace_id to ctx
  ├─ Metrics             http_request_duration_seconds, in-flight gauge
  ├─ RequestLog          structured access log (body/headers gated by env)
  ├─ Envelope            if HTTP_ENVELOPE_ENABLED, wrap raw JSON
  ├─ RequestMeta         stamp client IP + User-Agent on ctx
  │
  ├─ AuthenticationMiddlewareV2  (registrar-installed)
  │     • OPTIONS → next                  (CORS preflight)
  │     • path in exempt set → next       (built-ins + env + caller list)
  │     • Authorization: Bearer <jwt>     parse → ParseAccessToken
  │       └─ blacklist check (fail-open on lookup error)
  │       └─ inject AuthSession into ctx
  │
  ├─ RateLimit           (per-group: strict / default / skip)
  │
  └─ Handler             handler reads AuthSessionFrom(ctx)
                         returns JSON via WriteSuccess / WriteErrorEnvelope
                         or returns *AppError → AppErrorHandler envelopes it

UF-3 — Refresh token rotation

POST /auth/refresh  { refresh_token }
  │
  └─ TokenManager.Refresh(ctx, refreshToken)
       1. Parse              signature, exp, issuer, alg = HS256
       2. require token_type == "refresh"        else WRONG_TOKEN_TYPE
       3. store.IsActive(jti)                   else TOKEN_REVOKED
       4. store.Revoke(jti)                     one-shot rotation
       5. GeneratePair(user)                    new access + new refresh jti
       6. store.Save(newRefreshJti, sub, exp)
       7. return TokenPair { access, refresh, ttls, "Bearer" }

UF-4 — Graceful shutdown

SIGINT / SIGTERM
  │
  ├─ cancel engine ctx        (workers see ctx.Done())
  ├─ wait workers (≤ 10 s)    timeout → "workers shutdown timeout" log
  ├─ fiber.ShutdownWithContext (≤ 10 s)
  └─ runShutdownHooks (LIFO, ≤ 5 s)
        • DB pools close
        • Redis close
        • Mongo close
        • Firebase close
        • PubSub close
        • Storage close
        • OTel shutdown (flush spans)
        • Sentry flush
        • Heartbeat scheduler shutdown
        • GAE version watcher stop

UF-5 — App Engine warmup & wake-up

Two routes are mounted automatically by registerDefaultRoutes. Both are public (no auth) and idempotent.

  • GET /_ah/warmup — App Engine sends this before routing traffic to a new instance. Always returns 200 {status:1, code:"0000"}; the side-effect is that handler initialisation has already happened by the time the first user request arrives.
  • GET /wake-up — used by the in-process GAE version watcher. Returns the running app_id, app_version and env. When the watcher sees a version mismatch it logs and exits so the process restarts on the new build.

2.3 Page / Screen States

The closest analogue to UI states for this library is the readiness reported by /healthz and /readyz. Both endpoints render a HealthReport built by the service; the library only enforces the response shape.

The library validates incoming config (env) and incoming HTTP payloads (struct tags). There are no end-user forms.

HTTP payload validation

NewFiberApp wires NewValidator() as Fiber's StructValidator. Handlers call c.Bind().Body(&dto) and the validator runs go-playground/validator/v10 tags automatically; failures bubble up as *fiber.Error and the global AppErrorHandler converts them to a 400 request_error envelope.

2.5 Edge Cases

  • Boot without a database. Empty DB_NAME skips migration runner and OpenDB; infra.Database stays nil and any legacy helper that touches it returns infra.Database not initialized.
  • Boot without Redis. Rate limiter falls back to InMemoryRateLimitStore (per-pod counters, no cross-instance fairness). Blacklist init fails if it was the only configured store and JWT_BLACKLIST_ENABLED=true.
  • Mongo permission missing for createIndex. ensureAuthStoreIndexes runs in a goroutine with a 30 s deadline; failures are logged with component=auth, operation=ensure_indexes and the service continues without the index optimisation.
  • Blacklist lookup error. Auth V2 is fail-open on store errors — a transient Mongo blip does not lock everyone out. The lookup error is captured in the request log; switch to fail-closed only for endpoints where revocation must be authoritative.
  • Refresh token replay. The presented token is revoked before the new pair is issued (UF-3 step 4 before step 5). A second use of the same refresh token returns ErrRevokedToken.
  • Sentry / OTel exporter unreachable. Setup either succeeds and registers a shutdown hook, or returns an error and aborts boot. There is no degraded-observability mode — by design, ops should know.
  • Worker panics. Returned errors from a worker are logged with operation=worker_run; context.Canceled on shutdown is treated as the normal stop signal.
  • Cleanup hook hangs. Each phase has its own budget (10 s for Fiber, 5 s for hooks). Past the budget the process exits anyway; an "X shutdown timeout" warning lands in the log.
  • GAE version drift. If WAKE_UP_MINUTE is set and /wake-up reports a newer version than the running binary, the watcher logs and the instance restarts on the next request cycle.
